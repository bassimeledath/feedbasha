Making “switch to text” read as an action, not a status

The problem: a lone “✎ Text” button sitting mid-HUD looks like a label that says “you are in text mode.” Nothing signals it’s a toggle you click to switch. Four fixes below — click each to feel it flip. All also pull the control out of dead-center so it reads as a control.

Option A · recommended

Segmented selector · 🎤 Voice | ✎ Text

Both modes shown as a two-part switch; the active one is a solid pill. This is the universal “pick one of two” metaphor — impossible to misread as a status, and the inactive half obviously invites a click.

GoodZero ambiguity · both modes always visible · one tap
CostWidest of the four (~150px)
Option B

Verb label · “Switch to text”

Keep the single button but say the verb out loud, with a swap glyph: ⇄ Switch to text → ⇄ Switch to voice. The word “switch” removes all doubt.

GoodExplicit verb · compact-ish · one button
CostLonger text · current mode only implied (it’s “the other one”)
Option C

Swap icon · ⇄ Text

Same single button, minimal: a swap/exchange icon + the target mode. The ⇄ icon is a well-known “toggle” signal, so it reads as an action without spelling out “switch”.

GoodCompact · icon implies toggle · tidy
CostRelies on icon literacy · current mode still only implied
Option D

Sliding switch · 🎤 ⇢ ✎

A physical toggle: mic on the left, pencil on the right, a knob that slides to the active side. Reads unmistakably as “flip me,” and the knob shows current mode at a glance.

GoodStrong “switch” affordance · shows current state · fun
CostSlightly more chrome · two icons need learning first time
